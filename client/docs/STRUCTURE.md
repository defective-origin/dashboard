# [↤](../README.md) Structure

### Generate code parts like: hooks, tools, components and so on
```sh
yarn run gen
```

### Rules
- Dynamic and compiled folders, files should be added to `.gitignore` file
- All parts should be `modular` and `independent`
- Installed packages should has `override` and `passed through` appropriate project package
- All packages should has `index.ts` file to reexport all functionality except accumulate packages like `components` `screens` `pages` and so on
- Allowed file sub extensions: `component` `hooks` `tools` `constants` `context` `module` `test` `e2e` `stories` `hoc` `endpoint` `conf` `types` `launcher` `errors` `models` `ww(web-worker)` `sw(service-worker)` 

### Allowed folder structure
- __.vscode/__: contains config for ide
- __.storybook/__: contains settings for storybook previews
- __build/__: compiled app code
- __public/__: contains files which will be loaded by request after app render like `images` `videos` `content`
- __tests/__: contains configurations and settings for tests
- __docs/__: contains documentation which describe project and work on him
- __generator/__: templates and configs for generating application parts
	- __templates/__: contains all templates which can be used

- __legacy/__: legacy code base. Should be __cleared__ and moved to appropriate folder __before usage__. In most cases it's appears when code taken from other project

- __src/__
  - __assets/__: contains files which can be loaded with application like: `fonts` `icons`. Icons, images should be used via Icon, Image components

  - __features/__: contains components, tools and other functionalities for temporary feature
    - __FeatureName/__: contains code for one feature. After feature is approved all code should be merged into root app file structure 

  - __router/__: contains project routes, configs, guards, helpers, contexts, errors
  - __store/__: contains project store, configs, selectors, store slices and helpers
  - __types/__: contains global type definition in `d.ts` format. If it's possible this files should be placed nearby functionality what it for

  - __locale/__: contains localization configs, translates, helpers, tests
  	- __i18n__: contains `translates` for different languages in json format
  	- __l10n__: contains `formats` for different languages in json format

  - __tools/__: contains general `pure`, `unified`, `independent` code which can be moved into packages. Should reexport installed packages functionality and overrides through it.
    - __ToolName/__: contains one type functionalities and tests for them

  - __hooks/__: contains general `pure`, `unified`, `independent` hooks which can be moved into packages. Should reexport installed packages functionality and overrides through it.
  	- __UseHookName/__: contains one type functionalities and tests for them

  - __api/__: contains configs, tools, handlers, and other for network interaction
    - __routeName/__: contains endpoints, schemas, interceptors, types, errors of current route.
    - __auto/__: generated types, constants and so on. In most cases generated by `graphql`.

  - __theme/__: contains global theme styles, handlers, providers, configs, types
    - __styles/__: contains scss mixins, functions and variables

  - __App/__: contains env settings, app settings, app layout and launcher. App launcher accumulate all app configs providers like `locale`, `routing`, `api`, `theme`, `toasts`, `modals` and so on. Can be placed in apps if there is other apps like micro-frontend
  - __apps/__: contains components which use self or general config [component has postfix: App]
  - __pages/__: contains components which gets data from a api and spread them between components. Can be `lazy loadable`. Can only use: `Pages` `screens` `components` [component has postfix: Page]
  - __screens/__: contains components which gets data from a api and spread them between components. Can be `lazy loadable`. Can only use: `screens` `components`
  - __widgets/__: contains components for `CMS` which wrapped in `CMSAdapter` Hoc or component. Adapter should provide manager via context
  - __components/__: contains `pure`, `unified`, `independent` components without logic which gets data from props only. Can only use: `components`
    - __ComponentName/__: simple component
      - __SubComponentName/__: sub or private case of component which belong to component and styled for him and can be used only inside him
